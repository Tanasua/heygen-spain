# Покрокове налаштування

Орієнтовний час: **1,5–2 години**, більшість піде на Google Cloud і очікування.

Що знадобиться під рукою: акаунт GitHub, Google-акаунт, який керує **цільовим каналом**, ключ HeyGen, ключ OpenAI, Telegram.

> **Про точність цієї інструкції.** Логіку, назви API-ендпоінтів і структуру коду я перевірив. Але **інтерфейси Google Cloud, HeyGen і OpenAI змінюються часто**, тому назви кнопок і шляхи в меню можуть відрізнятися від описаних. Орієнтуйтеся на суть кроку, а не на дослівний шлях. Де я не впевнений — я це прямо позначив.

## ⚠️ Спочатку прочитайте це — два ризики, які можуть зупинити все

### Ризик 1: YouTube API може заливати відео тільки як приватні

Google обмежує проєкти, які не пройшли аудит для завантаження відео: відео, залиті через API такими проєктами, **можуть блокуватися в приватному статусі** незалежно від того, що просить код. Для вашої задачі це критично — сенс автоматики в публічних публікаціях.

**Наскільки я впевнений:** таке обмеження існує, я в цьому досить впевнений. А от чи діє воно у поточній редакції політики Google і в яких саме межах — **перевірити не можу**, доступу до мережі в мене немає, а політика могла змінитися.

**Що зробити:** на кроці 12 перший тест робиться саме для того, щоб це виявити. Якщо відео залишиться приватним — шукайте в Google Cloud Console форму запиту на аудит (YouTube API Services audit / compliance review). Розгляд займає тижні, тож починайте заздалегідь.

### Ризик 2: денна квота YouTube API — приблизно 6 заливок

Заливка одного відео коштує близько **1600 одиниць** квоти, типовий денний ліміт — **10 000**. Плюс встановлення обкладинки (~50) і перевірки каналу (кілька одиниць). Виходить **приблизно 6 відео на добу**.

Активний новинний канал-джерело публікує помітно більше. Тобто квота, а не сховище чи HeyGen, стане вашим справжнім вузьким місцем.

**Що зробити:** там же, у Google Cloud Console, подавайте запит на збільшення квоти. Це той самий довгий процес, тож робіть разом з аудитом.

## Крок 1. Репозиторій на GitHub

1. Створіть новий репозиторій — **приватний**. У ньому будуть лежати `processed.json` і робочі файли; секрети GitHub у приватному репо надійніше.
2. Розпакуйте архів і залийте вміст у репозиторій:

```bash
cd auto-dub-pipeline
git init
git add .
git commit -m "init: automation pipeline"
git branch -M main
git remote add origin https://github.com/ВАШ_ЮЗЕР/НАЗВА_РЕПО.git
git push -u origin main
```

**Важливо:** заплановані запуски (`schedule`) працюють **тільки з дефолтної гілки**. Тримайте все в `main`.

> **Про ліміти GitHub Actions.** Приватні репозиторії мають місячну безкоштовну квоту хвилин, і Workflow 1 тепер довгий — він чекає, поки HeyGen забере відео. Точні цифри квоти звіряйте в біллінгу GitHub, я їх підтвердити не можу. Публічний репозиторій ліміту хвилин не має, але тоді код і `processed.json` відкриті всім.

## Крок 2. Дозволити workflow писати в репозиторій

Пайплайн зберігає стан комітом у `data/processed.json`. Без права на запис це впаде.

**Settings → Actions → General → Workflow permissions** → виберіть **Read and write permissions** → **Save**.

У самих workflow я вже прописав `permissions: contents: write`, але налаштування на рівні репозиторію має бути не суворішим, інакше воно переважить.

## Крок 3. Google Cloud: проєкт і YouTube Data API

1. Відкрийте https://console.cloud.google.com/
2. Створіть новий проєкт (наприклад `youtube-es-automation`).
3. Переконайтеся, що вибрано саме цей проєкт — далі всі кроки в ньому.
4. **APIs & Services → Library** → знайдіть **YouTube Data API v3** → **Enable**.

---

## Крок 4. API-ключ для читання каналу-джерела

Це ключ лише для читання — для нього OAuth не потрібен.

1. **APIs & Services → Credentials → Create credentials → API key**.
2. Скопіюйте ключ — це буде `YOUTUBE_API_KEY`.
3. Рекомендую натиснути **Edit API key** і в **API restrictions** обмежити його лише YouTube Data API v3. Якщо ключ колись витече, ним не скористаються деінде.

---

## Крок 5. OAuth consent screen (тут головна пастка)

1. **APIs & Services → OAuth consent screen**.
2. User type: **External** (якщо у вас не Google Workspace).
3. Заповніть назву застосунку, свій email.
4. **Scopes** → додайте:
   - `https://www.googleapis.com/auth/youtube.upload`
   - `https://www.googleapis.com/auth/youtube`
5. У **Test users** додайте Google-акаунт, який керує цільовим каналом.

### 🔴 Обов'язково: переведіть застосунок у Production

Знайдіть статус публікації (**Publishing status**) і натисніть **Publish app**.

**Чому це критично:** поки застосунок у статусі *Testing*, виданий refresh token, за моїми даними, **перестає діяти приблизно через тиждень**. Автоматика просто зупиниться з помилкою авторизації, і ви будете гадати, чому. У статусі *Production* токен живе, доки ви його не відкличете.

Google може попросити верифікацію застосунку — для чутливих scope це нормально. Оскільки ви єдиний користувач, зазвичай достатньо пройти базові кроки; попередження «неверифікований застосунок» при вході можна прийняти вручну.

> Формулювання статусів і сама вимога верифікації в Google змінюються; конкретно про 7 днів для testing-режиму я **досить впевнений, але не на 100%**. Якщо через тиждень робота зупиниться з помилкою авторизації — причина майже напевно тут, просто перевидайте токен уже в Production-режимі.

## Крок 6. OAuth Client ID для іспанського канала

1. **APIs & Services → Credentials → Create credentials → OAuth client ID**.
2. Application type: **Desktop app**.
3. Назва — будь-яка.
4. Натисніть **Download JSON** — збережіть файл як `client_secret.json`.

У цьому файлі всередині є `client_id` і `client_secret` — це майбутні `YOUTUBE_ES_CLIENT_ID` і `YOUTUBE_ES_CLIENT_SECRET`.

## Крок 7. Отримати refresh token

Це робиться **локально, на комп'ютері з браузером** — не на сервері.

```bash
pip install google-auth-oauthlib
cd scripts
python get_refresh_token.py /шлях/до/client_secret.json
```

Відкриється браузер.

🔴 **Увійдіть тим акаунтом, який керує цільовим каналом.** Якщо акаунт має кілька каналів (бренд-акаунти), Google запитає, який вибрати — **виберіть цільовий**. Помилитесь тут — відео поїдуть на інший канал.

Скрипт виведе refresh token. Це `YOUTUBE_ES_REFRESH_TOKEN`.

Якщо скрипт скаже, що токен не видано — зайдіть на https://myaccount.google.com/permissions, приберіть доступ для цього застосунку і запустіть знову.

## Крок 8. Ключ HeyGen

У кабінеті HeyGen знайдіть налаштування API і скопіюйте ключ — це `HEYGEN_API_KEY`.

Точний шлях у меню назвати не можу — інтерфейс HeyGen я перевірити не можу. Шукайте розділ Settings / API / Developers.

**Про витрати:** пайплайн працює в режимі `precision` — він дає якісний ліп-синк, але коштує дорожче за `speed`. Порахуйте на своїх обсягах за тарифами HeyGen. Якщо задорого — у `scripts/heygen_client.py` змініть `DEFAULT_MODE = "precision"` на `"speed"`.

## Крок 9. Ключ OpenAI

1. https://platform.openai.com/api-keys → створіть ключ. Це `OPENAI_API_KEY`.
2. Переконайтеся, що на акаунті є баланс.
3. Раджу одразу виставити **usage limit** — на випадок, якщо щось піде в цикл.

Пайплайн викликає OpenAI двічі на відео: генерація тексту (дешево) і генерація фону обкладинки (основна вартість).

## Крок 10. Telegram-бот

1. Напишіть [@BotFather](https://t.me/BotFather) → команда `/newbot` → дайте ім'я.
2. BotFather видасть токен — це `TELEGRAM_BOT_TOKEN`.
3. **Напишіть своєму боту будь-яке повідомлення** — інакше він не має права писати вам першим.
4. Відкрийте в браузері:
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```
5. Знайдіть у відповіді `"chat":{"id":123456789` — це число і є `TELEGRAM_CHAT_ID`.

## Крок 11. Шрифт для обкладинок

Без жирного шрифту текст на обкладинці буде дрібним системним — виглядатиме зовсім не як ваші зразки.

1. Завантажте безкоштовний жирний шрифт з кириличною і латинською підтримкою — **Montserrat ExtraBold**, **Anton** або **Bebas Neue** (Google Fonts, ліцензія OFL — комерційне використання дозволене).
2. Покладіть `.ttf` у `assets/fonts/` під іменем `Montserrat-ExtraBold.ttf` (або змініть `FONT_PATH` у `process_new_video.py`).
3. Закомітьте:
   ```bash
   git add assets/fonts/ && git commit -m "add font" && git push
   ```

**Важливо про іспанську:** шрифт мусить містити діакритику — `á é í ó ú ñ ¡ ¿`. Перевірте на пробній генерації, що вони не перетворюються в порожні квадрати.

## Крок 12. Внести всі секрети в GitHub

**Settings → Secrets and variables → Actions → New repository secret.** Додайте по одному:

| Ім'я секрету | Звідки |
|---|---|
| `YOUTUBE_API_KEY` | крок 4 |
| `YOUTUBE_ES_CLIENT_ID` | `client_id` з `client_secret.json` (крок 6) |
| `YOUTUBE_ES_CLIENT_SECRET` | `client_secret` з того ж файлу |
| `YOUTUBE_ES_REFRESH_TOKEN` | крок 7 |
| `HEYGEN_API_KEY` | крок 8 |
| `OPENAI_API_KEY` | крок 9 |
| `TELEGRAM_BOT_TOKEN` | крок 10 |
| `TELEGRAM_CHAT_ID` | крок 10 |

Також додайте два **опційні** секрети, якщо користуєтесь ними:

| Ім'я секрету | Навіщо |
|---|---|
| `YOUTUBE_COOKIES` | вміст `cookies.txt` (формат Netscape) залогіненого YouTube-акаунта — без нього завантаження з датацентр-IP часто падає |
| `YT_DLP_PROXY_URL` | резидентний/ISP-проксі, `socks5://user:pass@host:port` |
| `INWORLD_API_KEY` | потрібен для типового (дешевого) шляху дубляжу |

### І одна змінна — не секрет

Хендл вихідного каналу навмисно не зашитий у код, щоб репозиторій не називав
конкретні канали. Додайте його як **variable**, не secret:

**Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**

| Ім'я | Значення |
|---|---|
| `SOURCE_CHANNEL_HANDLE` | хендл каналу-джерела, напр. `@example` |

Без цієї змінної `process_new_video.py` одразу впаде з явною помилкою — це
навмисно, щоб пайплайн не пішов мовчки не на той канал.

Імена мають збігатися **точно** — саме їх шукає код.

🔴 **Ніколи не комітьте `client_secret.json` у репозиторій.** Він уже в `.gitignore`? Перевірте: `git status` не повинен його показувати.

Скрипт позначить поточні відео як уже відомі. Автоматика підхопить лише те, що з'явиться далі.

## Крок 14. Перший тест — обов'язково в приватному режимі

Не запускайте одразу на публіку. Спершу зробіть так, щоб перше відео залилося приватним.

Відкрийте `scripts/youtube_uploader.py` і тимчасово змініть значення за замовчуванням:

```python
privacy_status: str = "private"   # було "public"
```

Закомітьте, запуште. Тепер запустіть вручну:

**Actions → Check & Process New Videos → Run workflow**

Слідкуйте за логом. Що має відбутися:

1. `Нових відео немає` — очікувано, якщо після bootstrap ще нічого не вийшло. Тоді дочекайтеся нового відео на каналі й запустіть знову.
2. Далі по логу: завантаження → `[tunnel] Публічний URL: https://...trycloudflare.com` → `[tunnel] Перевірка пройдена` → `[HEYGEN] Job створено` → відсоток відданого файлу → `[HEYGEN] Відео забрано повністю`.
3. У Telegram прийде «Відправлено на переклад».
4. Через якийсь час (precision-режим працює довго) запустіть вручну **Publish Translated Videos** — або дочекайтеся автоматичного запуску.
5. У Telegram прийде «Опубліковано», і відео з'явиться на іспанському каналі.

**Тут і перевіряйте Ризик 1:** відкрийте залите відео в YouTube Studio. Якщо ви ставили `private` і воно приватне — усе гаразд. Поверніть `"public"` і залийте наступне. Якщо ж відео **не дає перевести в публічний статус** — ви впіймалися на обмеження неаудованого проєкту, треба подавати заявку на аудит.

## Крок 15. Увімкнути автоматику

Коли тест пройшов і `privacy_status` повернуто в `"public"` — нічого додатково включати не треба, `schedule` у workflow вже активний:

- **Check & Process** — кожні 30 хв
- **Publish** — кожні 15 хв

Перевірити, що заплановані запуски йдуть, можна у вкладці **Actions** через годину.

> **Нюанс:** GitHub вимикає заплановані workflow у репозиторіях без активності (наскільки я пам'ятаю — після ~60 днів без активності, але точну цифру й те, чи рахуються автоматичні коміти бота як активність, підтвердити не можу). Оскільки пайплайн сам комітить стан, проблема, найімовірніше, не виникне. Якщо запуски раптом зупинились без помилок — зайдіть в Actions і увімкніть workflow вручну.

## Типові проблеми

| Симптом | Причина і що робити |
|---|---|
| `Помилка авторизації` / `invalid_grant` через тиждень роботи | OAuth consent screen залишився в статусі *Testing*. Опублікуйте застосунок (крок 5) і перевидайте refresh token (крок 7). |
| Відео залите, але застрягло приватним | Обмеження неаудованого проєкту (Ризик 1). Потрібна заявка на аудит. |
| `quotaExceeded` у логах Publish | Вичерпано денну квоту YouTube API (~6 заливок). Чекайте скидання квоти або подавайте запит на збільшення. |
| `git push` падає в кінці workflow | Крок 2 не зроблено — виставте Read and write permissions. |
| `TunnelError: Не отримав trycloudflare URL` | Тунель не піднявся. Перезапустіть workflow. Якщо повторюється систематично — переходьте на R2 (див. README). |
| `HeyGen не завантажив відео за 45 хв` | HeyGen не забрав файл, поки тунель був живий. Збільште `FETCH_TIMEOUT_SECONDS` у workflow або увімкніть `TRANSCODE_MAX_HEIGHT: "1080"`, щоб файл був меншим. |
| Текст на обкладинці — квадрати замість `ñ`, `á` | Шрифт без діакритики. Візьміть інший (крок 11). |
| Бот не пише в Telegram | Ви не написали боту першим (крок 10, пункт 3) або `TELEGRAM_CHAT_ID` неправильний. |
| Відео поїхало не на той канал | На кроці 7 вибрано не той канал. Відкличте доступ на https://myaccount.google.com/permissions і перевидайте токен. |

## Що варто робити регулярно

- **Перший тиждень** — заглядайте в Actions щодня. Саме тоді спливають проблеми з квотами, аудитом і токеном.
- **Дивіться на витрати** OpenAI і HeyGen після перших 10–20 відео, щоб зрозуміти реальну ціну одного ролика.
- **Перевіряйте якість** перших перекладів і обкладинок вручну. Промпти в `metadata_generator.py` і `thumbnail_generator.py` майже напевно захочеться підправити під ваш стиль — вони задумані як стартова точка, а не остаточний варіант.
