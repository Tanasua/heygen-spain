# Автоматизація перекладу відео @GlavredTV → @AHORAMISMO-b5e

## Що робить система

1. Кожні 30 хв перевіряє нові відео на https://www.youtube.com/@GlavredTV
2. Якщо відео коротше 6 хв → завантажує, перекладає іспанською з ліп-синком через HeyGen, генерує обкладинку та опис
3. Кожні 15 хв перевіряє, чи готовий переклад, і публікує на https://www.youtube.com/@AHORAMISMO-b5e
4. Якщо відео задовге або сталася помилка — надсилає повідомлення в Telegram

## 🚀 Як розгорнути

**Покрокова інструкція з розгортання й налаштування — у [SETUP.md](SETUP.md).** Там і про дві пастки, які можуть зупинити все (аудит YouTube API і квота на заливку), і про статус OAuth-застосунку, через який токен інакше згоряє за тиждень.

## ⚠️ Що потрібно налаштувати перед запуском

### 1. Як відео потрапляє в HeyGen (без платного сховища)

HeyGen приймає лише **публічно доступне посилання** на відео. Прямий upload файлу вам недоступний, платне сховище не потрібне — тож схема така:

1. Відео завантажується на диск раннера GitHub Actions.
2. На раннері піднімається локальний HTTP-сервер, що віддає цей один файл.
3. `cloudflared tunnel --url` створює публічний `https://xxx.trycloudflare.com` лінк — **без акаунта Cloudflare і без оплати**.
4. Лінк передається HeyGen.
5. Job **не завершується**, поки HeyGen не забере файл повністю.

**Ключова деталь.** З документації HeyGen не видно, коли саме він тягне відео — одразу при submit чи вже під час обробки. Тому пайплайн не вгадує за таймером, а **вимірює віддані байти**: сервер відслідковує покриття файлу Range-запитами і знає точний момент, коли віддано 100%. Далі витримується grace-період (2 хв) на випадок повторного звернення — і лише тоді тунель гаситься.

Плюс перевірка перед submit: тунель тестується запитом HEAD + 1 байт, і тільки якщо він реально маршрутизує до нашого сервера, посилання йде в HeyGen. Так ви не витрачаєте кредити HeyGen на битий лінк.

Нічого налаштовувати не потрібно — `cloudflared` завантажується автоматично при першому запуску.

#### ⚠️ Чесно про обмеження цієї схеми

**Cloudflare сам не рекомендує quick tunnels для продакшену.** Дослівно з того, що `cloudflared` виводить при старті:

> these account-less Tunnels have no uptime guarantee, are subject to the Cloudflare Online Services Terms of Use ... If you intend to use Tunnels in production you should use a pre-created named tunnel

Що це означає практично:
- **Немає гарантії доступності.** Тунель може не піднятися — тоді відео позначається `failed` і ви отримуєте повідомлення в Telegram. Втрати немає, але й публікації немає, доведеться перезапустити вручну.
- **Це сіра зона щодо ToS** для постійного автоматичного навантаження 24/7. Cloudflare залишає за собою право перевіряти використання. Ризик блокування quick tunnels для вашого трафіку існує — оцініть його самі.
- Я **не міг перевірити тунель наживо**: у середовищі, де я писав код, egress-проксі блокує `api.trycloudflare.com`. Бінарник, прапорці й формат виводу підтверджені; сам HTTP-сервер, Range-запити, трекінг байтів і логіку очікування я протестував реальними запитами. Але зв'язку «cloudflared → HeyGen» перевірите вже ви на першому запуску.

**Якщо тунель виявиться ненадійним** — у репозиторії лишився готовий модуль `scripts/r2_storage.py` на Cloudflare R2 (S3-сумісне сховище, egress безкоштовний). Щоб перейти: розкоментуйте `boto3` у `requirements.txt`, додайте R2-секрети і замініть виклик `_serve_and_submit()` у `process_new_video.py` на заливку в R2 + presigned URL. Ваш обсяг — кілька сотень мегабайт на кілька годин — майже напевно вкладається в безкоштовний tier, але точні ліміти звіряйте на https://developers.cloudflare.com/r2/pricing/ (я не маю мережевого доступу, щоб їх підтвердити).

### 1a. Опційно: зменшення файлу перед передачею

У тунеля немає гарантованої пропускної здатності, тож менший файл = коротша й надійніша передача. У workflow є змінна `TRANSCODE_MAX_HEIGHT`:
- `"0"` (типово) — передається оригінал як є.
- `"1080"` — відео перекодовується в H.264 CRF 21, 1080p перед передачею.

HeyGen на виході все одно віддає 1080p, тож тримати вихідні 20+ Мбіт/с сенсу мало. Якщо помітите деградацію обличчя в ліп-синку — знижуйте `crf` у `downloader.transcode_smaller()` (менше значення = вища якість).

### 2. Режим HeyGen: precision vs speed
`scripts/heygen_client.py` звірений з офіційною документацією HeyGen (v3 Video Translation API) і використовує режим **`precision`** — саме він дає якісний ліп-синк для talking-head відео з активною мімікою (ваш кейс). Це повільніше і дорожче за режим `speed`.

Якщо витрати на HeyGen виявляться зависокими — відкрийте `heygen_client.py` і змініть `DEFAULT_MODE = "precision"` на `DEFAULT_MODE = "speed"`. Ліп-синк буде помітно гірший, але обробка швидша і дешевша. Актуальні тарифи дивіться на https://www.heygen.com/pricing перед запуском на постійній основі.

### 3. Шрифт для обкладинок
Покладіть жирний `.ttf`-шрифт (наприклад, Montserrat ExtraBold, Anton, Bebas Neue) у `assets/fonts/Montserrat-ExtraBold.ttf` — без нього текст на обкладинці буде дрібним стандартним шрифтом.

## Налаштування GitHub Secrets

Перейдіть у **Settings → Secrets and variables → Actions** вашого репозиторію та додайте:

| Secret | Опис |
|---|---|
| `YOUTUBE_API_KEY` | API-ключ з Google Cloud Console (YouTube Data API v3 увімкнено) — для читання даних з @GlavredTV |
| `OPENAI_API_KEY` | Ключ з platform.openai.com |
| `HEYGEN_API_KEY` | Ключ з налаштувань акаунта HeyGen |
| `TELEGRAM_BOT_TOKEN` | Токен бота, створеного через @BotFather |
| `TELEGRAM_CHAT_ID` | Ваш chat_id (дізнатись: написати боту, потім відкрити `https://api.telegram.org/bot<TOKEN>/getUpdates`) |
| `YOUTUBE_ES_CLIENT_ID` | OAuth Client ID для іспанського каналу |
| `YOUTUBE_ES_CLIENT_SECRET` | OAuth Client Secret |
| `YOUTUBE_ES_REFRESH_TOKEN` | OAuth Refresh Token з правами `youtube.upload` для акаунта, що керує @AHORAMISMO-b5e |

### Як отримати YOUTUBE_ES_REFRESH_TOKEN
1. У Google Cloud Console створіть OAuth Client ID (тип "Desktop app").
2. Локально одноразово пройдіть OAuth-флоу (google-auth-oauthlib) із залогіненим акаунтом власника @AHORAMISMO-b5e, з scope `https://www.googleapis.com/auth/youtube.upload`.
3. Збережіть отриманий `refresh_token` — він не має терміну дії, доки ви не відкличете доступ.

## Структура репозиторію

```
.github/workflows/
  check_and_process.yml   # запускається кожні 30 хв
  publish.yml              # запускається кожні 15 хв
scripts/
  state_manager.py         # робота з data/processed.json
  youtube_monitor.py        # перевірка нових відео
  downloader.py              # завантаження через yt-dlp
  tunnel_server.py           # HTTP-сервер з Range + трекінг відданих байтів
  cloudflared_tunnel.py      # quick tunnel + перевірка працездатності
  r2_storage.py              # НЕ використовується: fallback на Cloudflare R2
  heygen_client.py           # переклад через HeyGen v3 API (precision mode)
  thumbnail_generator.py     # обкладинка: OpenAI фон + Pillow текст
  metadata_generator.py      # title/description іспанською через OpenAI
  youtube_uploader.py        # заливка на іспанський канал
  telegram_notifier.py       # сповіщення
  process_new_video.py       # оркестратор Workflow 1
  publish_pending.py         # оркестратор Workflow 2
data/
  processed.json           # стан оброблених відео (комітиться автоматично)
  thumbnails/              # обкладинки між Workflow 1 і 2, видаляються після публікації
assets/fonts/               # сюди покласти .ttf шрифт для обкладинок
```

## Обмеження, про які варто пам'ятати

- **Workflow 1 тепер довгий.** Він тримається живим, поки HeyGen забирає відео (типово хвилини, ліміт очікування — 45 хв, `FETCH_TIMEOUT_SECONDS`). Cron спрацьовує кожні 30 хв, тож запуски можуть ставати в чергу — це нормально, `concurrency` не дає їм накладатись.
- **Диск раннера** ~14 ГБ. Відео видаляється одразу після того, як HeyGen його забрав — до викликів OpenAI.
- **Порядок кроків підібраний під витрати**: OpenAI (генерація обкладинки — найдорожча операція) викликається ТІЛЬКИ після успішної передачі відео в HeyGen. Якщо тунель не піднявся, платних викликів не буде.
- **Cron у GitHub Actions** може запускатись із затримкою 5–10 хв у пікові періоди.
- **YouTube API квоти** — заливка витрачає ~1600 одиниць з денного ліміту 10000 (типово ~6 заливок/день на дефолтній квоті). Це, ймовірно, стане вашим справжнім вузьким місцем, а не сховище: судячи зі скріншотів, канал публікує більше 6 відео на день. Квоту можна розширити через заявку в Google Cloud Console.
- **Обкладинки в git.** Кожна ~200 КБ, видаляється після публікації, але лишається в історії репозиторію. За рік це сотні мегабайт. Якщо почне муляти — раз на кілька місяців можна почистити історію або перейти на R2.
- **Ліміт хвилин GitHub Actions.** Приватні репозиторії мають безкоштовну квоту хвилин на місяць; довгі job (очікування HeyGen) її їдять. Публічний репозиторій — без ліміту, але тоді код і `processed.json` відкриті. Точні квоти звіряйте в налаштуваннях біллінгу GitHub — я не маю доступу, щоб їх підтвердити.
