# Auto-dub pipeline: @GlavredTV → @AHORAMISMO

Бот, який сам знаходить нові відео на російськомовному новинному каналі,
перекладає їх іспанською (голосом, схожим на оригінальний диктора),
малює обкладинку, пише заголовок/опис/теги і публікує на іспанський
YouTube-канал. Людина в процесі не бере участі.

Працює повністю на GitHub Actions — свого сервера немає.

---

## Як це працює

```
YouTube (@GlavredTV)
      │  кожні 30 хв: чи є нове відео?
      ▼
  yt-dlp ──────────────► mp4 на раннері
      ▼
  Whisper ─────────────► транскрипт з таймкодами (63 сегменти)
      ▼
  групування ──────────► 13 кусків по ~15 с
      ▼
  GPT-4.1 ─────────────► іспанський переклад
      ▼
  Inworld TTS ─────────► клон голосу диктора + синтез іспанською
      ▼
  ffmpeg ──────────────► підгонка темпу + заміна аудіодоріжки
      ▼
  GPT-4.1 + gpt-image-2 ► заголовок, опис, теги, обкладинка
      ▼
  YouTube Data API ────► публікація на @AHORAMISMO
      ▼
  Telegram ────────────► сповіщення власнику
```

Реальний прогін від початку до публікації — **~4 хвилини**.

## Ключові рішення

**Чому не HeyGen.** HeyGen робить ліп-синк, але коштує ~$4/хв відео через
API. Ми зібрали свій конвеєр із окремих сервісів — виходить на кілька
порядків дешевше. Платимо тим, що губи диктора не збігаються зі звуком.
Для формату «ведучий за столом + відеовставки» це прийнятно. Код HeyGen
лишився як ручний фолбек (`DUB_PROVIDER=heygen`).

**Голос.** Inworld клонує голос оригінального диктора з 6–14 с зразка і
говорить ним іспанською. Модель `inworld-tts-2` — cross-lingual, тобто
намагається говорити цільовою мовою без акценту оригіналу.

**Чому озвучуємо кусками по 15 с, а не по реченню.** Іспанський переклад
майже завжди довший за російський оригінал. Якщо підганяти під таймкод
кожне окреме речення, темп стрибає: одне тараторить, сусіднє жується. На
довшому куску надлишок і недостача сусідніх реплік взаємно гасяться.
Плюс темп жорстко обмежений діапазоном **0.92–1.15x** — краще розійтися з
таймкодом на частку секунди, ніж зіпсувати звук.

**Обкладинки.** Один запит до `gpt-image-2`, який малює і фон, і
тривимірний заголовок одразу (Pillow поверх картинки давав плоский
аматорський результат). Макет обирається з **ротації 9 дизайнів**,
знятих із реальних обкладинок українських новинних каналів — інакше вся
стрічка виглядає однаково і CTR падає. Вибір детермінований за `video_id`:
для конкретного відео результат відтворюваний.

**Стан.** `data/processed.json` у самому репозиторії — які відео вже
оброблені, з яким статусом і результатом. Ніякої бази даних.

## Захист від перевитрат

- **Максимум 5 прогонів на добу** сумарно на весь пайплайн, незалежно від
  успішності. Cron спрацьовує 48 разів, але окремий gate-job рахує
  запуски через GitHub API і глушить решту.
- Дорогі виклики OpenAI (обкладинка) робляться **тільки після** того, як
  дубляж успішно готовий. Впало раніше — платних викликів не було.
- `MAX_VIDEOS_PER_RUN` обмежує кількість відео за один прогін.

## Стек

| Крок | Чим |
|---|---|
| Пошук нових відео | YouTube Data API v3 |
| Завантаження | yt-dlp (+ резидентний проксі, cookies) |
| Транскрипція | OpenAI Whisper (`whisper-1`) |
| Переклад | OpenAI `gpt-4.1` |
| Синтез мови | Inworld TTS (`inworld-tts-2`) |
| Аудіо/відео | ffmpeg |
| Обкладинка | OpenAI `gpt-image-2` |
| Публікація | YouTube Data API v3 (OAuth) |
| Сповіщення | Telegram Bot API |
| Оркестрація | GitHub Actions |

## Скільки це коштує

**~$0.40 за відео** середньої довжини (≈7 хв), або **~$0.056 за хвилину
відео**.

> ⚠️ Це **розрахунок, а не дані з рахунків**. Тривалість відео заміряна
> (429 с у середньому по опублікованих), ставки звірені у вересні 2026,
> але кількість токенів і символів оцінена з тривалості. Похибка ±40%.
> Щоб отримати точну цифру, треба логувати `usage` з кожного виклику API.

| Стаття | Ставка | На 7-хв відео |
|---|---|---|
| Whisper (`whisper-1`) | $0.006/хв | $0.043 |
| GPT-4.1 — переклад | $2 / $8 за 1M токенів in/out | ~$0.027 |
| GPT-4.1 — заголовок, опис, теги | те саме | ~$0.004 |
| Inworld TTS-2 — синтез | $25 за 1M символів | ~$0.16 |
| `gpt-image-2` — обкладинка (`quality=high`) | ~$0.165 за зображення | ~$0.17 |
| GitHub Actions | ~4.5 хв раннера | $0 (у межах безкоштовного ліміту) |
| **Разом** | | **≈ $0.40** |

Окремо й поза цією таблицею — **фіксована місячна плата за проксі**,
незалежна від кількості відео.

Клонування голосу в Inworld безкоштовне — платимо лише за синтез.

**Де основні гроші.** Обкладинка і озвучка дають ~83% вартості. Якщо
треба здешевити, найшвидший важіль — `quality="medium"` в
`thumbnail_generator.py`: обкладинка дешевшає приблизно вчетверо
(~$0.04), усе відео виходить у ~$0.27. Платимо якістю картинки.

**Для порівняння.** HeyGen precision (ліп-синк), від якого відмовились —
$0.0667/с, тобто $4.00/хв. Те саме 7-хвилинне відео коштувало б **~$29**
замість $0.40. Різниця приблизно у 70 разів — це і є причина, чому
конвеєр зібраний вручну з окремих сервісів.

**Стеля витрат.** При ліміті 5 прогонів на добу максимум — близько
**$60/міс** на API. Реально менше: не кожен прогін знаходить нове відео.

## Проксі та доступ до YouTube

Це виявилось найбільшою технічною проблемою проєкту, і вона нікуди не
зникла — просто утримується.

YouTube розпізнає IP-адреси дата-центрів (а всі раннери GitHub Actions
саме такі) і віддає їм `Sign in to confirm you're not a bot` замість
відео. Причому не завжди — блок плаваючий, тож симптом легко сплутати з
чим завгодно іншим.

Що допомагає, у порядку важливості:

1. **Резидентний / ISP-проксі зі статичним IP.** Купується окремо
   (ми брали ISP-проксі, не датацентрові й не ротаційні — rotating
   тут шкодить: yt-dlp має ходити з одного IP усю сесію завантаження).
   Передається секретом `YT_DLP_PROXY_URL` у форматі
   `socks5://user:pass@host:port`.
2. **Cookies залогіненого YouTube-акаунта** — секрет `YOUTUBE_COOKIES`,
   вміст `cookies.txt` у форматі Netscape. Протухають і їх треба
   періодично оновлювати вручну.

Дві окремі граблі тут:

- для `socks5://` **yt-dlp потребує пакета `PySocks`** — без нього
  проксі просто не працює;
- секрет `YT_DLP_PROXY_URL` довго існував у репозиторії, але
  `downloader.py` його **ніколи не читав** — проксі був куплений і
  мовчки ігнорувався. Ніякої помилки при цьому не видно: просто
  час від часу падає завантаження.

Пробували обійтися без проксі через сторонній сервіс-завантажувач
(Apify, безкоштовний тариф) — актор повертав порожній результат,
причину так і не встановили. Відкотились на yt-dlp.

## Граблі, на які наступили

Коротко, щоб не повторювати:

| Проблема | Як проявлялась | Рішення |
|---|---|---|
| **Версія OpenAI SDK** | Підняли `openai` до `2.x` заради `gpt-image-2` — Whisper почав віддавати `404`, весь дубляж упав | Тримаємо `openai==1.51.0`, а в Images API ходимо напряму через `requests`, повз SDK |
| **Ліміт Whisper 25 МБ** | Довге відео не влазило в один запит | Віддаємо не WAV, а mp3 64 kbps; якщо все одно завелике — автоматично знижуємо бітрейт |
| **Переклад губив репліки** | GPT на 225 сегментах в одному запиті повертав 220 перекладів | Пачки по 40 + повтор + фолбек «по одному елементу», де розбіжність неможлива |
| **Сильний акцент у голосі** | Іспанська звучала з російською вимовою | `inworld-tts-1.5` не cross-lingual. Перейшли на `inworld-tts-2` + явний параметр `language` + клонування голосу одразу з `langCode` цільової мови |
| **Клацання між репліками** | Чутні щиглики на стиках сегментів | 8 мс fade-in/fade-out на краях кожного куска |
| **Рвана вимова** | Одне речення тараторить, сусіднє жується | Озвучення кусками ~15 с + клемп темпу 0.92–1.15x (див. вище) |
| **Плоскі обкладинки** | Заголовок накладався через Pillow поверх картинки — виглядало аматорськи | Одним запитом до `gpt-image-2`, який малює текст як частину сцени |
| **Одноманітні обкладинки** | Усі схожі одна на одну, стрічка «зливається» | Ротація 9 різних макетів |
| **Обрізаний текст на обкладинці** | Генерували 1536×1024 (3:2), кроп до 16:9 зрізав нижній рядок напису | Генеруємо 1568×896 (ratio 1.75) — кроп ~7 px |
| **Telegram-бот як вхід** | Хотіли віддавати боту файл руками — не вийшло | Bot API дозволяє боту **завантажити** файл максимум 20 МБ. Відео важать 60+ МБ. Ідея відкинута до реалізації |
| **Circuit breaker вимкнув прод** | Після помилки на тестовій гілці автоматика вимкнула workflow | Вимкнення workflow через GitHub API діє **на весь репозиторій**, не на гілку. Логіку прибрали, натомість зробили денний ліміт |
| **`__pycache__` у комітах** | Сміття потрапляло в репо | У проєкті просто не було `.gitignore` |

## Відомі обмеження

- Немає ліп-синку.
- Українська мова не входить до GA-списку Inworld — якість клонування з
  українського джерела не гарантована (джерело зараз російськомовне).
- Доступ до YouTube тримається на проксі + cookies (див. вище); cookies
  треба періодично оновлювати вручну — це поки що єдина ручна операція.
- `openai` SDK закріплений на `1.51.0`: на `>=2.0.0` Whisper починає
  віддавати 404 (перевірено на реальному прогоні).
